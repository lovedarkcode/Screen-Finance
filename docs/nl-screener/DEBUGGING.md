# Empty Energy screen investigation — 18 October 2026

## Findings and root causes

Read-only PostgreSQL inspection found **16 stock records and 173 financial records**, with eight Indian and eight US listings. All sixteen have validated snapshots. `universe_count` is a stock count in the selected market with at least one `validation_version=1` financial row, measured before exchange, sector, industry, numeric and sorting-currency filters. It is not a result count, a financial-row count, a page-size limit, or total exchange coverage. There is no hidden eight-stock SQL limit. The refresh command defaults to the explicit sixteen-symbol starter list in `ingestion.py`; other validated symbols can be imported via command arguments or `--symbols-file`.

Only **RELIANCE.NS** is classified Energy in the imported Indian dataset. Its stored figures are:

| Metric | Value | Reporting period |
|---|---:|---|
| Annual revenue growth | 9.591238% | 2026-03-31 versus 2025-03-31 |
| Trailing P/E | 21.93408× | Provider TTM; exact end unavailable |

The growth calculation is `(10,572,190,000,000 / 9,646,930,000,000 - 1) * 100`, using two comparable annual revenues in INR. RELIANCE fails growth >15% and P/E <20 independently. Zero matches remain correct after fixing the date-handling gap. `status: success` means screening completed successfully; an empty result is valid.

The submitted JSON contains explicit `2026-10-18` fiscal-end restrictions. The query builder correctly treated these as exact dates, which cannot match the available annual end or the provider P/E with unknown end. No frontend, schema or query-builder default sets today's date. The code and supplied response cannot establish whether these particular dates were selected in the editor or generated by NVIDIA; the original request body was not supplied. Investigation did identify a parser-validation gap: it checked explicitly mentioned dates but accepted extra model-generated dates when no date was requested. This is now fixed and regression-tested. Manually entered structured dates remain intentional exact constraints; they are never silently changed.

The old structured execution endpoint deliberately had no prompt input and returned the response model's empty-string default. The frontend used that endpoint for edits, sorting and pagination, losing source prompt context. Natural-language search already carried its query through the workflow. Structured execution now accepts optional context, and absence is represented by null. Result cache entries never retain a previous caller's prompt; cache hits attach the current request's context.

## Query and integrity verification

- One shared allowlisted SQLAlchemy plan now drives both production results and development diagnostics. Values remain bound parameters; no model-generated SQL or arbitrary identifiers are executable.
- Outer joins select one latest validated row per stock and reporting basis using `row_number`, with deterministic ties. All numeric conditions are ANDed; exact-date selections check per-metric provenance as well as row dates. Missing latest values remain unavailable, without substituting an older profitable period.
- Revenue growth uses recomputed, comparable annual revenues with a positive prior denominator and the same reporting currency. It is a percentage, so a reporting currency different from the listing currency does not require FX conversion. Monetary thresholds and sorting still enforce compatible currency.
- P/E uses the provider's `trailingPE`, never forward P/E or annual profit as an invented TTM denominator. Known non-positive trailing EPS, or non-positive P/E, cannot qualify as low P/E. These values are omitted on future ingestion and excluded/hidden for existing rows. Invalid P/E sorts as unavailable. Annual losses alone do not disqualify a positive TTM metric.
- Per-metric source, fiscal date, input values and validation status remain attached to results. Provider P/E retains an unknown exact end even when another TTM metric in the same row has a known date.
- Sector filters normalize casing/aliases and compare trimmed provider sector values. No production data was added, refreshed, or fabricated during this investigation; no database migration was required.

# Exchange alternatives regression (2026-10-18)

The request containing `NSE or BSE` was rejected by a blanket OR guard before NVIDIA ran. Exchange alternatives now use an allowlisted `exchanges` list and a bound SQL `IN` predicate; financial conditions remain conjunctive. Single-exchange clients retain the existing `exchange` field. Mixed-market or conflicting exchange selections are rejected. Financial OR still returns an explicit unsupported response rather than silently dropping conditions.

A second validation defect consumed punctuation commas after numeric thresholds, marking them as uncovered numbers when NVIDIA copied the condition without the comma. Numeric tokens now stop at punctuation. Explicit annual periods may use the documented annual default. Sort validation recognizes `Sort the results by`. The editor preserves exchange alternatives and arbitrary supported result limits such as top 20. The cache schema version was bumped to prevent old parse entries from being reused.
